# ToneLab

> **Comprendre avant de régler.**

Le ToneLab est un projet de recherche, de documentation technique et d'expérimentation consacré au matériel de guitare, à la conception du son et à la construction d'identités sonores.

L'objectif n'est pas simplement de constituer une collection de presets.

Le projet cherche à comprendre **pourquoi un réglage fonctionne**, comment les différents éléments interagissent et comment construire des configurations reproductibles à partir du matériel réellement utilisé.

# Expérimentations

Les expérimentations constituent la partie opérationnelle du projet.

Elles permettent de conserver les configurations réellement testées, leurs réglages, leurs observations et leur statut.

La documentation méthodologique et les expérimentations sont volontairement séparées :

Les tests peuvent ainsi évoluer indépendamment des chapitres documentaires.

# Philosophie du ToneLab

Le ToneLab ne cherche pas à reproduire aveuglément des réglages trouvés sur Internet.

La démarche consiste à :

1. identifier une caractéristique sonore recherchée ;
2. comprendre les éléments qui contribuent à cette caractéristique ;
3. déterminer comment l'obtenir avec le matériel disponible ;
4. expérimenter ;
5. comparer les résultats ;
6. conserver les configurations pertinentes ;
7. valider progressivement les profils.

Les profils sonores sont donc des **interprétations adaptées au matériel utilisé**, et non des copies exactes de configurations extérieures.

Cette philosophie constitue le principe directeur de l'ensemble de la documentation.

---

# Relation avec ToneLab Profiles

L'application ToneLab Profiles constitue l'outil de travail associé à cette démarche.

Elle permet notamment de gérer :

* le catalogue de matériel ;
* les amplificateurs ;
* les cabinets ;
* les guitares ;
* les pédales ;
* les configurations utilisées lors des tests ;
* les réglages ;
* les observations ;
* les statuts.

La distinction fondamentale est la suivante :

> **Le catalogue décrit ce qu'est le matériel. Le test décrit comment ce matériel a été utilisé lors d'une expérimentation.**

Cette organisation permet de réutiliser un même élément matériel dans plusieurs configurations sans dupliquer sa définition.

La documentation Markdown conserve quant à elle les connaissances, la méthode, les analyses et les conclusions issues de ces expérimentations.

# Évolution du projet

Le ToneLab est une documentation vivante.

De nouvelles sections pourront être ajoutées lorsque de nouvelles recherches ou expérimentations justifieront leur intégration.

L'architecture privilégie volontairement le contenu réellement construit plutôt qu'une liste de chapitres théoriquement prévus.

Le projet peut ainsi évoluer progressivement sans remettre en cause les fondations déjà documentées.
