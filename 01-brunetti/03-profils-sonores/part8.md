<a id="part8-configuration"></a>

## 2. Une expérimentation = une configuration

Une expérimentation correspond à une configuration concrète essayée dans le cadre d'une recherche.

Cette configuration peut comprendre :

* une guitare ;
* un accordage ;
* un pickup ;
* un cabinet ;
* un amplificateur ;
* un canal ;
* des réglages d'amplification ;
* des pédales ;
* des réglages de pédales.

Elle peut également être associée à une référence musicale et à un objectif précis.

Le principe retenu est simple :

> **1 expérimentation = 1 configuration documentée**

Cette règle permet de conserver une trace claire de chaque approche essayée.

Elle évite notamment de remplacer un ancien réglage par un nouveau sans conserver l'information correspondante.

---

<a id="part8-identification"></a>

## 3. Identifier les expérimentations

Chaque expérimentation doit pouvoir être distinguée des autres.

Un identifiant permet notamment de retrouver rapidement une configuration et de suivre son évolution.

Les identifiants utilisés dans ToneLab permettent par exemple de distinguer plusieurs recherches autour d'une même référence.

Ainsi, plusieurs tests peuvent être associés à un même artiste ou à un même objectif sans être confondus.

L'identifiant ne décrit donc pas nécessairement la qualité du résultat.

Il sert avant tout à identifier l'expérimentation.

---

<a id="part8-objectif"></a>

## 4. Définir un objectif

Une expérimentation est plus utile lorsqu'elle répond à une question précise.

L'objectif peut concerner :

* un territoire sonore ;
* une référence musicale ;
* un canal ;
* une guitare ;
* une pédale ;
* un cabinet ;
* une combinaison de plusieurs éléments.

Par exemple :

> **Chercher une base Stoner dense**

constitue un objectif différent de :

> **Chercher une base Rock dynamique**

Même si les deux recherches peuvent utiliser une partie du même matériel.

L'objectif permet ensuite d'interpréter correctement le résultat.

Un son peut être intéressant pour un objectif et inadapté pour un autre.

---

<a id="part8-variable"></a>

## 5. Modifier une variable à la fois

Lorsque cela est possible, il est préférable de limiter le nombre de changements effectués entre deux essais.

Si l'on modifie simultanément :

* le canal ;
* la guitare ;
* le cabinet ;
* la Tube Screamer ;
* l'égalisation ;

il devient difficile de déterminer ce qui a réellement produit la différence.

Une approche plus contrôlée consiste à conserver une configuration de référence et à modifier progressivement les éléments étudiés.

Par exemple :

1. configuration de départ ;
2. modification du canal ;
3. comparaison ;
4. retour ou conservation du changement ;
5. modification suivante.

Cette méthode n'interdit pas les changements importants.

Elle permet simplement de conserver une relation compréhensible entre une modification et son effet.

---

<a id="part8-historique"></a>

## 6. Conserver les essais précédents

Un essai abandonné ne doit pas nécessairement être supprimé.

Il peut contenir une information utile pour la suite de la recherche.

Conserver les essais permet notamment de retrouver :

* une configuration déjà testée ;
* une combinaison qui avait été écartée ;
* un réglage qui pourra être réévalué ;
* une piste qui avait donné un résultat intéressant dans un autre contexte.

Cette conservation est particulièrement importante lorsqu'une recherche s'étend sur plusieurs sessions.

Il devient alors possible de reprendre le travail sans repartir de zéro.

---

<a id="part8-comparaison"></a>

## 7. Comparer plusieurs configurations

Lorsque plusieurs configurations sont disponibles, elles doivent être comparées par rapport au même objectif.

La comparaison peut porter sur :

* le caractère général ;
* la dynamique ;
* l'attaque ;
* la définition ;
* la densité ;
* l'équilibre tonal ;
* la réaction aux différentes techniques de jeu ;
* la cohérence avec la référence musicale.

Une configuration ne doit pas être retenue simplement parce qu'elle est différente.

La différence doit être interprétée par rapport à l'objectif recherché.

Une modification importante peut donc être inutile, tandis qu'une modification plus discrète peut améliorer significativement le résultat.

---

<a id="part8-variantes"></a>

## 8. Organiser les variantes

Plusieurs expérimentations peuvent partir d'une même configuration de référence.

Une variante peut notamment concerner :

* la guitare ;
* le pickup ;
* l'accordage ;
* le cabinet ;
* le canal ;
* le Gain ;
* l'égalisation ;
* une pédale ;
* le réglage d'une pédale.

Il est important de distinguer la variante de l'expérimentation elle-même.

La variante représente une différence par rapport à une configuration de référence.

L'expérimentation constitue le résultat concret de cette modification.

Cette distinction permet de comparer plusieurs approches sans multiplier inutilement les profils définitifs.

---

<a id="part8-observations"></a>

## 9. Documenter les observations

Les réglages ne suffisent pas toujours à expliquer le résultat obtenu.

Les observations doivent permettre de conserver ce qui a été entendu ou constaté pendant l'essai.

Elles peuvent notamment préciser :

* ce qui fonctionne ;
* ce qui fonctionne moins bien ;
* ce qui change après une modification ;
* les limites rencontrées ;
* les éléments à tester lors du prochain essai.

Une observation utile doit rester liée à l'expérimentation.

Il est préférable d'écrire :

> « Le son devient plus dense mais perd de l'attaque lorsque le Gain augmente. »

plutôt qu'une appréciation trop générale comme :

> « Meilleur son. »

L'objectif est de conserver suffisamment d'information pour comprendre la décision prise ensuite.

<a id="part8-statuts"></a>

## 10. Utiliser les statuts

Les statuts permettent de suivre l'état d'une expérimentation.

ToneLab utilise actuellement quatre statuts :

* **À tester**
* **Prometteur**
* **Validé**
* **Rejeté**

Ils correspondent à des niveaux différents d'avancement.

### À tester

La configuration constitue une piste de recherche qui n'a pas encore été suffisamment évaluée.

### Prometteur

Le résultat présente un intérêt réel mais nécessite encore une comparaison ou une validation.

### Validé

La configuration répond suffisamment bien à l'objectif pour être conservée comme référence.

### Rejeté

La configuration ne répond pas suffisamment à l'objectif recherché.

Le statut ne constitue donc pas une note de qualité absolue.

Il décrit l'état de la recherche.

---

<a id="part8-profil"></a>

## 11. Du test au profil retenu

Une recherche peut produire plusieurs tests.

Tous ne deviendront pas des profils de référence.

La progression consiste à comparer les différentes configurations et à identifier celles qui répondent le mieux à l'objectif.

Une configuration peut ainsi passer de :

**À tester**

à :

**Prometteur**

puis éventuellement à :

**Validé**.

Les autres configurations peuvent rester documentées avec leur statut correspondant.

Cette organisation permet de conserver l'historique tout en évitant de transformer chaque expérimentation en profil définitif.

Le profil retenu représente donc l'aboutissement d'une recherche, et non simplement le premier réglage qui a donné un résultat intéressant.

---

<a id="part8-documentation"></a>

## 12. Relation entre documentation et expérimentations

La documentation Markdown et les données d'expérimentation n'ont pas exactement le même rôle.

La documentation explique :

* les principes ;
* la méthode ;
* les conclusions ;
* les profils retenus ;
* les connaissances acquises.

Les données de ToneLab conservent davantage le détail des expérimentations :

* les configurations ;
* les réglages ;
* les observations ;
* les statuts ;
* les différentes tentatives.

Cette séparation évite de transformer la documentation en journal exhaustif de chaque essai.

Elle permet également de conserver les expérimentations sans alourdir inutilement les chapitres Markdown.

---

<a id="part8-progressive"></a>

## 13. Principe de recherche progressive

Une recherche sonore peut évoluer progressivement.

Il n'est pas nécessaire de déterminer immédiatement le réglage final.

La méthode consiste plutôt à :

1. définir un objectif ;
2. établir une première configuration ;
3. réaliser un essai ;
4. observer le résultat ;
5. identifier ce qui doit évoluer ;
6. réaliser un nouvel essai ;
7. comparer les résultats ;
8. conserver les configurations utiles ;
9. valider ou rejeter progressivement les pistes.

Cette méthode permet de transformer une recherche parfois intuitive en démarche documentée.

Elle laisse également la possibilité de revenir sur une décision lorsque de nouvelles expérimentations apportent des informations supplémentaires.

---

<a id="part8-a-retenir"></a>

## 14. À retenir

L'organisation des expérimentations doit permettre de rechercher un son sans perdre l'historique de cette recherche.

Les principes essentiels sont :

* documenter chaque configuration essayée ;
* donner un objectif à chaque expérimentation ;
* identifier clairement les tests ;
* limiter autant que possible les changements simultanés ;
* conserver les essais précédents ;
* comparer les configurations par rapport à l'objectif ;
* documenter les observations ;
* utiliser les statuts pour suivre l'avancement ;
* distinguer les expérimentations des profils finalement retenus.

Cette organisation permet de construire progressivement une bibliothèque de profils à partir d'expérimentations réelles, tout en conservant la trace des choix effectués.
