<a id="part7-pourquoi"></a>

## 2. Pourquoi valider un profil ?

Un réglage intéressant lors d'un premier essai ne constitue pas nécessairement un profil fiable.

Le résultat peut dépendre :

* du volume utilisé ;
* de la guitare ;
* du cabinet ;
* des pédales ;
* du morceau joué ;
* de la manière de jouer ;
* des conditions d'écoute.

La validation a donc pour objectif de vérifier que le résultat obtenu correspond réellement à l'objectif défini.

Elle permet notamment de distinguer :

> **un son qui paraît intéressant**
> d'un
> **son qui peut être retenu comme référence.**

La validation ne cherche pas à démontrer qu'un profil est objectivement « meilleur ».

Elle cherche à déterminer s'il répond suffisamment bien à l'objectif pour pouvoir être conservé et réutilisé.

---

<a id="part7-hypothese"></a>

## 3. De l'hypothèse au test

Une expérimentation commence généralement par une hypothèse.

Par exemple :

> le canal Boost pourrait produire une meilleure base pour un territoire Rock dynamique que le XLead.

Cette hypothèse doit ensuite être transformée en test.

Le test doit préciser la configuration utilisée et permettre d'observer le résultat.

L'intérêt de cette méthode est de ne pas confondre :

* ce que l'on pense devoir fonctionner ;
* ce qui a réellement été essayé ;
* ce qui a effectivement donné un résultat intéressant.

Une hypothèse peut donc être correcte, incorrecte ou partiellement correcte.

Dans tous les cas, le test fournit une information utile.

---

<a id="part7-comparaison"></a>

## 4. Construire une comparaison fiable

Une comparaison est plus informative lorsque les éléments non étudiés restent aussi constants que possible.

Si l'on cherche à comparer deux canaux, il est préférable de conserver autant que possible :

* la même guitare ;
* le même pickup ;
* le même accordage ;
* le même cabinet ;
* les mêmes pédales ;
* un niveau de volume comparable.

On peut alors observer plus clairement l'influence du canal.

La même logique s'applique lorsque l'on compare :

* deux réglages de Gain ;
* deux positions de Tube Screamer ;
* deux égalisations ;
* deux cabinets ;
* deux guitares.

Il n'est pas toujours possible de maintenir tous les paramètres identiques.

Mais plus la comparaison est contrôlée, plus la conclusion est exploitable.

---

<a id="part7-criteres"></a>

## 5. Les critères d'évaluation

Un profil peut être évalué selon plusieurs critères.

Les principaux sont :

* **caractère sonore** : le résultat appartient-il bien au territoire recherché ?
* **dynamique** : le son réagit-il correctement au jeu ?
* **attaque** : les attaques restent-elles suffisamment lisibles ?
* **définition** : les notes et les accords restent-ils distincts ?
* **densité** : le son possède-t-il l'épaisseur recherchée ?
* **équilibre tonal** : graves, médiums et aigus sont-ils cohérents ?
* **cohérence musicale** : le résultat fonctionne-t-il avec la référence étudiée ?
* **reproductibilité** : peut-on retrouver le résultat à partir de la configuration documentée ?

Tous ces critères n'ont pas nécessairement la même importance.

Un profil destiné à un son massif pourra privilégier la densité.

Un profil destiné à un riff très articulé pourra au contraire privilégier l'attaque et la définition.

La validation doit donc toujours être effectuée par rapport à l'objectif initial.

---

<a id="part7-contexte"></a>

## 6. Le rôle du contexte musical

Un réglage peut sembler excellent lorsque l'on joue seul et fonctionner moins bien dans un morceau.

L'évaluation doit donc, lorsque cela est possible, être réalisée dans le contexte musical pour lequel le profil est recherché.

Cela permet notamment de vérifier :

* la place des médiums ;
* la lisibilité des riffs ;
* la présence du grave ;
* la définition des accords ;
* la dynamique ;
* la capacité du son à rester identifiable dans un mix.

Un son très impressionnant seul n'est donc pas nécessairement le meilleur profil pour jouer avec un groupe.

Le contexte musical constitue une partie du critère de validation.

---

<a id="part7-volume"></a>

## 7. Tester à volume différent

Le comportement perçu d'un amplificateur peut évoluer avec le niveau de volume.

Un profil qui paraît équilibré à faible volume peut devenir :

* trop chargé en graves ;
* trop agressif dans les aigus ;
* trop compressé ;
* ou au contraire plus équilibré lorsque le volume augmente.

Il est donc préférable de ne pas valider définitivement un profil après une seule écoute à un seul niveau.

Lorsque les conditions le permettent, le profil doit être vérifié à plusieurs niveaux de volume.

L'objectif n'est pas d'obtenir exactement le même son à tous les volumes.

Il s'agit de vérifier que le comportement général reste cohérent avec l'objectif.

---

<a id="part7-materiel"></a>

## 8. Comparer les configurations matérielles

La validation doit tenir compte du matériel utilisé.

Une configuration comprenant :

* une Gibson Les Paul Classic DC ;
* un Brunetti XL R-EVO II ;
* un cabinet donné ;
* une Tube Screamer ;

ne doit pas automatiquement être considérée comme validée avec une autre guitare ou un autre cabinet.

Une modification du matériel peut nécessiter une adaptation du réglage.

Dans ToneLab, ces éléments peuvent être conservés directement dans le test afin de garder le contexte de l'expérimentation.

Le catalogue décrit le matériel disponible, tandis que le test décrit la configuration effectivement utilisée.

Cette distinction permet de conserver une validation précise sans dupliquer inutilement les éléments du catalogue.

---

<a id="part7-modification"></a>

## 9. Déterminer si une modification apporte réellement quelque chose

Une modification ne doit pas être conservée simplement parce qu'elle change le son.

Elle doit apporter une amélioration par rapport à l'objectif recherché.

Par exemple, augmenter le Gain peut produire davantage de saturation sans nécessairement améliorer le profil.

De même, ajouter une Tube Screamer ou une égalisation peut modifier fortement le son sans pour autant le rendre plus pertinent.

Il faut donc se demander :

> **La modification améliore-t-elle réellement le résultat par rapport à l'objectif ?**

Si la réponse est non, il est préférable de revenir à la configuration précédente.

Cette approche limite l'accumulation de réglages et permet de conserver une chaîne de décision compréhensible.

---

<a id="part7-prometteur"></a>

## 10. Passer de Prometteur à Validé

Le statut **Prometteur** indique qu'une configuration présente un intérêt réel mais qu'elle nécessite encore une vérification.

Le passage à **Validé** peut intervenir lorsque plusieurs conditions sont réunies :

* le territoire sonore recherché est clairement identifiable ;
* la configuration répond à l'objectif ;
* les principaux paramètres sont suffisamment documentés ;
* le résultat a été vérifié dans le contexte prévu ;
* aucune modification évidente ne permet d'obtenir un résultat nettement meilleur ;
* le réglage peut être retrouvé ultérieurement.

La validation n'exige pas nécessairement une perfection absolue.

Elle signifie que le profil est suffisamment fiable pour devenir une référence de travail.

Le statut peut également évoluer ultérieurement si de nouvelles expérimentations montrent qu'une autre configuration est plus pertinente.

---

<a id="part7-rejete"></a>

## 11. Rejeter une configuration

Le rejet constitue également un résultat utile.

Une configuration peut être rejetée parce qu'elle :

* s'éloigne trop du territoire recherché ;
* manque de définition ;
* possède trop de graves ;
* manque de dynamique ;
* devient trop compressée ;
* fonctionne mal avec la guitare utilisée ;
* dépend trop fortement d'une configuration matérielle particulière ;
* ou ne présente simplement pas d'avantage suffisant par rapport à une autre solution.

Le rejet ne signifie pas que le réglage est mauvais dans l'absolu.

Il signifie qu'il ne répond pas suffisamment bien à l'objectif de l'expérimentation.

Conserver ces résultats permet d'éviter de revenir plus tard vers une piste déjà explorée sans raison.

---

<a id="part7-trace"></a>

## 12. Conserver une trace de la validation

La validation doit laisser une trace suffisamment précise pour comprendre pourquoi une configuration a été retenue.

Les informations importantes sont notamment :

* la référence musicale ;
* la guitare ;
* le pickup ;
* l'accordage ;
* le cabinet ;
* l'amplificateur ;
* le canal ;
* les réglages ;
* les pédales ;
* les réglages des pédales ;
* les observations ;
* le statut final.

Les valeurs qui n'ont pas été mesurées ou réellement testées ne doivent pas être inventées.

Un champ incomplet est préférable à une valeur fictive.

Cette règle est particulièrement importante pour conserver la fiabilité de la documentation.

---

<a id="part7-progressive"></a>

## 13. Principe de validation progressive

La validation ne doit pas être considérée comme une étape unique située à la fin de la recherche.

Elle accompagne progressivement l'expérimentation.

Une configuration peut ainsi évoluer selon une logique simple :

**À tester → Prometteur → Validé**

ou :

**À tester → Rejeté**

Une configuration Prometteuse peut également revenir à **À tester** lorsqu'une nouvelle question nécessite une expérimentation supplémentaire.

De même, un profil déjà Validé peut être réévalué si une nouvelle configuration apporte des résultats significativement meilleurs.

La validation constitue donc un état de la connaissance disponible à un moment donné, et non une vérité définitive.

---

<a id="part7-a-retenir"></a>

## 14. À retenir

La validation permet de transformer progressivement les expérimentations en profils fiables.

Elle repose principalement sur :

* une hypothèse clairement identifiée ;
* une configuration documentée ;
* des comparaisons aussi contrôlées que possible ;
* des critères adaptés à l'objectif ;
* une écoute dans le contexte musical ;
* une vérification avec le matériel réellement utilisé ;
* la conservation des résultats intéressants comme des résultats rejetés.

Le statut **Validé** ne signifie pas qu'un profil est universel ou définitif.

Il signifie qu'il constitue, à ce stade du projet, une référence suffisamment fiable pour être conservée et réutilisée.

La méthode de validation complète ainsi les parties précédentes : elle permet de passer de la construction d'un réglage à la constitution progressive d'une bibliothèque de profils documentés.
